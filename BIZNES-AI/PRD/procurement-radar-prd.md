## 1. Проблема

Отдел закупок у малого/среднего импортёра работает вслепую:

| Ситуация | Последствие |
|----------|-------------|
| Нет прогноза по спросу | Заказывают "на глаз" — то перезаказ, то дефицит |
| Lead time 45–90 дней (импорт) | Когда видят дефицит — уже поздно |
| Нет единого экрана по всем SKU | Байер открывает 3–4 источника чтобы понять что заказать |
| Нет алертов | Дефицит замечают когда клиент уже жалуется |
| תוקף не отслеживается в разрезе рентабельности | Заказывают лишнее → списания |

**Клиентский профиль (ICP):**
- Израильский импортёр / дистрибьютор: БАД, косметика, медизделия, продукты
- 50–500 SKU
- 1–5 человек в отделе закупок
- Priority ERP (или аналог) — но данные достают вручную
- Power BI есть, но viewer без контроля (или вообще нет)

**Примеры:** TevaСom Import (витамины, косметика, линзы), аналогичные импортёры Петах-Тиква / Ашдод / ТА

---

## 2. Продукт — что это

**Procurement Radar** — веб-приложение для байера.  
Один экран. Вся картина по SKU. Умные алерты. Кнопка "שלח הזמנה".

**Не CRM, не ERP, не BI-платформа.**  
Узкий инструмент: **вижу что кончается → понимаю когда → заказываю правильно.**

---

## 3. Пользователи

| Роль | Кто | Что делает в системе |
|------|-----|----------------------|
| **Buyer** (קניין) | 1–2 человека | Смотрит алерты, утверждает/редактирует заказы, отправляет поставщику |
| **Manager** (מנהל רכש) | 1 человек | Видит KPI, настраивает пороги, смотрит историю |
| **Read-only** | CEO / финансы | Только просмотр дашборда |

## 4. Core Features — MVP

### 4.1 SKU Dashboard — главный экран

Таблица всех активных SKU с колонками:

| Колонка | Источник | Описание |
|---------|----------|----------|
| שם מוצר / מק"ט | ERP | Название + артикул |
| מלאי נוכחי | ERP live | Единиц на складе |
| מכר ממוצע / יום | ERP 90д | Дневная скорость продаж |
| **ימי מלאי** | Расчёт | Сколько дней хватит при текущем темпе |
| **ימי ליד טיים** | Настройки | Lead time от поставщика по этому SKU |
| **סטטוס** | Логика | 🔴 DANGER / 🟡 WARNING / 🟢 OK |
| הזמנה מוצעת | Алгоритм | Рекомендуемое кол-во к заказу |
| תוקף קרוב | ERP | Ближайшая дата истечения |

**Цветовая логика статуса:**
- 🔴 DANGER: `ימי מלאי < ליד טיים` → уже опоздали, заказывать срочно
- 🟡 WARNING: `ימי מלאי < ליד טיים × 1.5` → окно заказа открывается
- 🟢 OK: запас достаточный

### 4.2 Forecast Engine

Прогноз продаж на 90 дней вперёд на основе:
- История продаж 18–24 месяца
- Сезонность (Prophet / ARIMA)
- Детектирование аномалий (резкий рост/падение)

Выход прогноза влияет на `ימי מלאי` — считается не по текущему среднему, а по прогнозу.

**AI-усиление (Phase 2):**
- Claude API анализирует паттерн и даёт text-инсайт: "Vitamin D растёт x2.3 в Oct–Feb, рекомендую увеличить safety stock на 40%"
- Детектор аномалий: резкий всплеск → алерт → байер смотрит причину

### 4.3 Alert Center

Уведомления в реальном времени:

| Тип алерта | Триггер | Канал |
|------------|---------|-------|
| 🔴 Критический дефицит | `ימי מלאי < ליד טיים` | Email + WhatsApp |
| 🟡 Окно заказа | `ימי מלאי < ליד טיים × 1.5` | Email |
| ⚠️ Аномальный рост продаж | Отклонение > 2σ | Email + app |
| 📅 תוקף через N дней | Настраиваемый порог | Email |
| 📦 Заказ не подтверждён | Заказ создан > 48ч назад без ответа | WhatsApp |

### 4.4 Order Builder — предзаказ

1. Байер видит SKU со статусом WARNING/DANGER
2. Система предлагает `הזמנה מוצעת` = (прогноз × (ליד טיים + safety stock buffer)) − текущий остаток
3. Байер редактирует кол-во вручную если нужно
4. Нажимает "שלח הזמנה" →
   - Генерируется PDF/Excel заказа поставщику
   - Запись в историю
   - Опционально: отправка email поставщику напрямую

### 4.5 Supplier Management

Для каждого поставщика:
- Список SKU
- Lead time (дни)
- MOQ (минимальный заказ)
- Контакт (email для автоотправки)
- История заказов

## 5. Технический стек

```
Priority ERP (или WooCommerce API)
        ↓
   SQL Server / REST sync (daily или real-time)
        ↓
   Node.js Backend API
        ↓
   Prophet (Python microservice) — forecasting
        ↓
   React / Next.js PWA — UI для байера
        ↓
   Claude API — text insights + anomaly explanation
        ↓
   WhatsApp Business API — критичные алерты
```

**Хостинг:** VPS/Azure (как Formula Road)  
**Auth:** простой JWT, роли Buyer / Manager / ReadOnly

## 6. Scope — что НЕ входит в MVP

- ❌ Полная ERP-интеграция (двусторонняя запись в Priority) — Phase 2
- ❌ B2C / клиентский модуль

- ❌ Мобильное приложение (MVP — адаптивный веб)
- ❌ Мультискладовость (MVP — один склад)
- ❌ Автоматическая отправка заказа без апрува байера

## 7. Модель монетизации

### Ценообразование

| Пакет | Что включено | Цена |
|-------|-------------|------|
| **Setup** | Подключение к ERP, настройка SKU, lead times, пороги, обучение | **15,000–25,000 ₪** |
| **Forecast add-on** | Prophet engine + AI инсайты | **+8,000–12,000 ₪** |
| **SaaS monthly** | Хостинг + поддержка + обновления + алерты | **1,500–2,500 ₪/мес** |

**Итого первый год:** ~45,000–55,000 ₪ (setup + 12 мес SaaS)

### Почему платят регулярно

- Данные обновляются ежедневно — нужен сервер
- Алерты по WhatsApp — операционная зависимость
- Прогноз пересчитывается — нужна поддержка модели
- Байер не может без системы — sticky продукт

## 8. Конкурентная позиция

| Альтернатива | Слабость |
|-------------|---------|
| Excel вручную | Нет прогноза, нет алертов, ошибки |
| Power BI viewer (Bionit) | Read-only, нет предзаказа, нет WhatsApp |
| SAP/Oracle | Дорого, долго, избыточно для 50–500 SKU |
| NetSuite | $2,000+/мес, нет иврита, нет приоритета |

**Позиционирование BIZNES-AI:** "מחיר סטארט-אפ, מומחיות Priority" — быстро, дёшево, на иврите, знают Priority изнутри.
