# Excel Smart Reports — стандарт COLUMBUS

Каждый .xlsx, который генерирует Claude в этом проекте, должен выглядеть и вести себя как файл, сделанный человеком в Excel: с настоящими таблицами, а не просто закрашенными диапазонами. Ниже — накопленные правила, часть из которых стоила часов разбора реальных поломок файлов (сессия SADRAN_ANALYSIS.xlsx, 2026-07-21/22).

## Когда применять

Всегда, когда пишешь новый .xlsx или добавляешь лист/таблицу в существующий — отчёты, экспорты, сравнения периодов, планограммы, финансовые сводки. Не жди, что пользователь произнесёт "сделай красиво" — это дефолт.

## Правило №0 (главное) — для ЗАПИСИ новых .xlsx используй xlsxwriter, не openpyxl

**История вопроса:** на книге с 12+ Excel Table на разных листах и ~1300 строк данных openpyxl стабильно генерировал файл, который Excel открывал с "We found a problem with some content in '...xlsx'. Do you want us to try to recover?". Перебрано и **отклонено** несколько гипотез, прежде чем найдена настоящая причина:

- ❌ Дублирующийся `id` у Table (см. Правило №1 ниже) — реальный баг, но фикс **не устранил** порчу файла на масштабе.
- ❌ Ручной `border` на каждой ячейке (раздувает `styles.xml`) — сокращение с тысяч уникальных `cellXfs` до 14 **не устранило** порчу.
- ✅ **Подтверждено бисекцией**: минимальный файл из официальной документации openpyxl (`ws.append()`, 1 таблица, TableStyleMedium9) открывается чисто. Синтетический тест **той же структуры**, что и реальная книга (12 таблиц, одна на 1307 строк), пересобранный через **xlsxwriter** вместо openpyxl — тоже открывается чисто. Значит дело не в конкретной настройке, а в том, что openpyxl ненадёжен для ЗАПИСИ новых книг такого масштаба (много Table + много строк), независимо от того, что именно ты написал через его API.

**Как действовать:**
- Для **чтения** существующего .xlsx (в том числе источника данных для отчёта) — openpyxl нормально: `openpyxl.load_workbook(path, data_only=True, read_only=True)`.
- Для **записи** нового .xlsx с несколькими Excel Table и от пары сотен строк — используй `xlsxwriter`. Готовый переиспользуемый хелпер: `scripts/xlsxwriter_smart_table.py` (`make_formats()`, `write_table()`, `add_bar_chart()`).
- Референс полной книги на 18 листов, xlsxwriter, без единой ошибки: `scripts/build-sadran-analysis.py`.
- Небольшая (1 лист, десяток строк) книга через openpyxl, скорее всего, откроется без проблем — но раз xlsxwriter не даёт этого класса багов вообще, дешевле использовать его всегда, чем каждый раз гадать, где проходит граница "маленький/большой" файл.
- **Проверяй не пересохранением через ту же библиотеку** (openpyxl `load_workbook()` **не ловит** свои же баги — он лояльнее, чем сам Excel), а прямым разбором XML внутри zip-архива: `xl/tables/*.xml` well-formed, нет дублей `id`, `xl/worksheets/_rels/*.rels` резолвятся. См. сниппет в конце файла.

## Правило №1 — не трогай существующий файл, где может быть PivotTable/VBA/именованные диапазоны

Это отдельный, независимый риск от Правила №0 — актуален, даже если пишешь через xlsxwriter, но пытаешься ОТКРЫТЬ И ПЕРЕСОХРАНИТЬ существующий файл. `openpyxl` (и в меньшей степени `exceljs`) может **молча** повредить сложные workbook-и при перезаписи: PivotTable-кэш, VBA-макросы, именованные диапазоны, сложное условное форматирование, внешние связи — при повторном сохранении Excel может отказаться открывать файл или предложить "recovery", теряя часть содержимого. Задокументированный баг с тем же поведением: https://github.com/anthropics/claude-code/issues/22044

**Как действовать:**
1. Перед тем как открыть существующий .xlsx на запись — проверь, есть ли в нём `ws._pivots`, макросы (`.xlsm`), именованные диапазоны или сложное conditional formatting.
2. Если да — **не пересохраняй этот файл**. Читай из него только данные (`data_only=True, read_only=True`), а результат пиши в **новый** файл (`ИмяИсходника_ANALYSIS.xlsx` рядом), через xlsxwriter (см. Правило №0).
3. Скажи об этом пользователю коротко (риск + что делаешь вместо), не жди вопроса.

## Правило №2 — если всё-таки используешь openpyxl для записи, Table должен иметь уникальный `id`

Если пишешь через openpyxl (маленький файл, 1-2 таблицы) — держи в голове: `openpyxl.worksheet.table.Table(displayName=..., ref=...)` по умолчанию создаёт **id=1 у каждой таблицы**. `displayName` может быть уникальным, а `id` — нет, и именно `id` обязан быть уникальным во всей книге по спецификации OOXML. Инкрементируй `id` вручную тем же счётчиком, что и `displayName`. (В xlsxwriter эта проблема не возникает — `add_table()` сам не создаёт коллизий id.)

## Правило №3 — обязательный чек-лист для каждой таблицы

- **Настоящий Excel Table** (`ws.add_table()` — и в xlsxwriter, и в openpyxl), не просто закрашенный диапазон + ручной autofilter
- **Freeze panes** на первой строке данных (заголовок остаётся видимым при скролле)
- **Автофильтр** — включается автоматически вместе с Table; не ставь отдельный `auto_filter`/фильтр на том же диапазоне — дублирование, тоже триггерит предупреждение о повреждении
- **Жирный шрифт** в заголовках, тёмно-синий фон `#1F4E79` / `#1F4E78`, белый текст — либо стилем Table (`Table Style Medium 2`), либо явным форматом
- **Цветовое кодирование по статусу**, где уместно (рост/падение, ok/ошибка):
  - ✅ хорошо / כן / найден → светло-зелёный `#C6EFCE`/`#E2EFDA`, текст `#006100`
  - ❌ плохо / لא / ошибка → светло-красный `#FFC7CE`/`#FCE4D6`, текст `#9C0006`
  - ⚠️ предупреждение → светло-жёлтый `#FFF2CC`
  - — нейтральный → светло-серый `#F2F2F2`
- **Правильная ширина колонок** — не обрезать текст (посчитать max длину значения в колонке + запас)
- **Не заливай border на каждую ячейку вручную** при сотнях-тысячах строк — раздувает `styles.xml`; полосы строк и границы отдаёт стиль самой Table (`showRowStripes=True`)
- **Ручной `cell.border`/border-формат — только на заголовке и итоговой строке**, не на теле таблицы
- **Стиль таблицы** — `TableStyleMedium2` (чередование строк) как дефолт

## Правило №4 — отступы и структура листа

- Колонка A и строка 1 остаются пустыми/узкими — визуальный отступ от края листа (актуально для "обзорных"/summary-листов; для листов, где весь лист = одна таблица, можно начинать с A1/строки 1 — так проще для xlsxwriter add_table)
- В конце таблицы, где уместна сумма — отдельная **Total/סה"כ строка**, жирным шрифтом

## Правило №5 — никогда не Merge Cells

Если нужен визуально объединённый заголовок над несколькими колонками — **"Center Across Selection"** (`centerContinuous` alignment), не merge. Merge ломает сортировку, фильтрацию и копирование данных внутри Table; Center Across Selection даёт тот же внешний вид без побочных эффектов.

## Правило №6 — считай агрегаты из сумм, а не усредняй готовые проценты

Когда строишь сводные метрики (% изменения, рост/падение) по группам — сначала суммируй абсолютные величины (`SUM(last_year)`, `SUM(now)`) внутри группы, **потом** вычисляй процент от сумм. Никогда не усредняй уже готовую колонку `%` из исходных данных — при неравных базах это даёт неверный Total. Актуально для любых сравнений периодов (YoY, месяц к месяцу, план/факт).

## Правило №7 — безопасность при чтении чужих .xlsx

`openpyxl` по умолчанию не защищён от XML-бомб (billion laughs, quadratic blowup) при чтении файла из недоверенного источника. Если файл пришёл не от пользователя напрямую (вложение из письма, скачанный откуда-то) — используй `defusedxml` или хотя бы не открывай файлы с неизвестным происхождением без предупреждения пользователя.

## Правило №8 — formula/DDE-инъекция при ЗАПИСИ внешних данных (xlsxwriter)

Подтверждено эмпирически (security-review 2026-07-22): `xlsxwriter`'s `ws.write(row, col, val)` детектирует тип по содержимому строки — если `val` начинается с `"="`, xlsxwriter пишет её как **живую формулу** (`<f>...</f>` в XML), не как текст. Проверено на `"=cmd|'/c calc'!A1"` (классический DDE-payload) — попадает в файл как формула, которая исполнится при открытии.

Любая колонка с данными из внешнего источника (PBI, CRM, Excel-импорт от пользователя) — имя клиента, город, название SKU, комментарий — потенциально может начинаться с `=` (опечатка, копипаст-артефакт, OCR) и не контролируется кодом отчёта. Это CWE-1236 (Formula Injection), применимо к нативному `.xlsx` (не только CSV).

**Как действовать — НЕ через `ws.write_string()`.** Первая попытка фикса (`write_string()` вместо `write()`) сама оказалась багом: на книге с >10 Excel Table `write_string()` в xlsxwriter 3.2.9 стабильно ломает файл ("problem with some content") — подтверждено бисекцией 2026-07-22 (17 таблиц + `write_string()` = поломка; те же 17 таблиц + `write()` = чисто). Правильный фикс — на уровне конструктора книги:

```python
wb = xlsxwriter.Workbook(OUT, {"strings_to_formulas": False})
```

Это отключает автодетект `"=..."` как формулы **для всей книги**, при этом код продолжает использовать обычный `ws.write()` — тот путь, который не ломается на масштабе. Готовый паттерн — `scripts/xlsxwriter_smart_table.py`.

## Данные — без хардкода

Читай данные для отчёта из источника (сам .xlsx, SQL, Power BI DAX) **на каждом запуске скрипта**, не зашивай числа в массивы в коде — иначе на следующий период придётся руками переписывать генератор. См. также `pbi-to-pptx-pipeline` skill для той же философии применительно к PPTX.

## Пример использования

`scripts/xlsxwriter_smart_table.py`:
1. `make_formats(wb)` — единый набор форматов на книгу (заголовок, growth/decline, деньги, %, italic-note)
2. `write_table(ws, fmt, start_row0, headers, rows, pct_col_idx=, money_cols=, table_name=)` — пишет данные + создаёт Table поверх; заголовок пишет `add_table()` сам, вручную его дублировать не нужно
3. `add_bar_chart(wb, ws, title, sheet_name, cat_col0, val_col0, first_row0, last_row0, anchor=)` — простой bar chart по диапазону

Полный рабочий пример на 18 листов, несколько чартов, RTL — `scripts/build-sadran-analysis.py`.

## Проверка файла на повреждение (не через ту же библиотеку)

```python
import zipfile, xml.etree.ElementTree as ET

def check_xlsx(path):
    z = zipfile.ZipFile(path)
    issues = []
    for n in z.namelist():
        if n.endswith(('.xml', '.rels')):
            try:
                ET.fromstring(z.read(n))
            except Exception as e:
                issues.append(f"{n}: {e}")
    ids = []
    for n in z.namelist():
        if n.startswith("xl/tables/table") and n.endswith(".xml"):
            ids.append(ET.fromstring(z.read(n)).get("id"))
    if len(ids) != len(set(ids)):
        issues.append("Duplicate table ids")
    return issues
```
