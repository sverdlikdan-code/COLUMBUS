# Yuval Agent — PRD

**Version:** 1.0
**Date:** 2026-06-18
**Status:** Draft

---

## Description

`Yuval` — агент-креатив COLUMBUS. Генерирует изображения для презентаций и слайдов, сохраняя визуальную последовательность с уже существующими референс-изображениями проекта. Использует MCP-инструмент `generate_image` (Google Nano Banana 2) через скилл `nano-banana-2`.

Отвечает CEO. Вызывается напрямую `Yael` (за изображениями для статей) или пользователем/CEO напрямую.

---

## Problem It Solves

Сгенерированные изображения без анализа референса выглядят несвязанными — разный стиль, палитра, композиция от слайда к слайду. `Yuval` решает это, всегда сначала анализируя `reference/`, и только потом составляя prompt, который наследует визуальный язык проекта.

---

## Goals

1. **Визуальная консистентность** — каждое новое изображение выглядит частью одной серии с `reference/`
2. **Точечное применение стиля** — извлекать из референса только то, что релевантно конкретному запросу, не весь стиль целиком
3. **Предсказуемое именование** — единый формат файлов в `outputs/`
4. **Прозрачный отчёт** — пользователь/вызывающий агент всегда получает полный путь к файлу

---

## Scope

### In Scope

- Сканирование `reference/` (png, jpg, jpeg, webp, gif)
- Анализ стиля, цветовой палитры, композиции, визуальных элементов референса
- Составление prompt по Prompt Formula (запрос + стиль + палитра + элементы + mood)
- Вызов MCP `generate_image` через скилл `nano-banana-2`
- Сохранение в `outputs/` с именем по конвенции `<topic>-<YYYYMMDD>-<HHmm>.png`

### Out of Scope (v1)

- Редактирование уже существующих изображений (только генерация новых)
- Видео или анимация
- Доступ к внешним источникам изображений кроме `reference/`
- Финальное одобрение визуала (это зона `Guy`, если активирован)

---

## Inputs / Outputs

### Inputs

- Запрос на изображение (от пользователя, CEO или Yael)
- Референс-изображения в `reference/` (если есть)
- `GEMINI_API_KEY` (переменная окружения, настраивается пользователем — никогда не хардкодить)

### Outputs

- Файл изображения в `outputs/<topic>-<YYYYMMDD>-<HHmm>.png`
- Отчёт вызывающему: имя файла + полный путь

---

## Architecture

```text
Trigger (CEO / пользователь / Yael)
        │
        ▼
      Yuval
  ├─ Сканировать reference/
  ├─ Анализ: стиль / палитра / композиция / элементы
  ├─ Извлечь компоненты релевантные запросу
  ├─ Составить prompt (Prompt Formula)
  ├─ Вызвать nano-banana-2 → generate_image
  └─ Сохранить в outputs/ + отчёт о пути
```

---

## Prompt Formula

```
[запрос пользователя], [стиль из reference], [цветовая палитра из reference],
[релевантные визуальные элементы], [quality/mood keywords]
```

---

## Reference Analysis Guide

| Категория | Что определять |
|-----------|-----------------|
| Стиль | фотографический / иллюстрация / минималистичный / винтажный / современный |
| Палитра | 2–4 доминирующих цвета, тон (warm/cool/neutral), насыщенность |
| Композиция | centered / rule of thirds / symmetrical / close-up / wide / aerial |
| Элементы | текстуры, освещение, тени, повторяющиеся детали |

---

## Quality / Acceptance Criteria

- [ ] `reference/` всегда сканируется перед генерацией (даже для простых запросов)
- [ ] Извлекаются только релевантные компоненты стиля, не весь референс целиком
- [ ] `fileName` всегда задан по конвенции — никогда не оставлен пустым
- [ ] Минимальное качество генерации — `balanced` (не `fast`) для финальных изображений
- [ ] Отчёт о завершении всегда содержит полный путь к файлу

---

## Error Handling

- `reference/` пуста → продолжить без анализа стиля, сообщить: "Нет референсных изображений — создаю только по запросу"
- `GEMINI_API_KEY` не настроен / MCP-сервер недоступен → сообщить пользователю, что нужно настроить переменную окружения, не пытаться угадать ключ
- `generate_image` вернул ошибку → сообщить причину, не повторять запрос бесконечно

---

## Security

- `GEMINI_API_KEY` задаётся пользователем в `.env`, никогда не хардкодится в коде агента
- Не публикует и не загружает изображения во внешние сервисы кроме вызова MCP `generate_image`
- Все выходные файлы остаются локально в `outputs/`
