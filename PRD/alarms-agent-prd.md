# PRD: Alarms Agent — администратор алярмов COLUMBUS

## Проблема
Автоматические письма разбросаны по трём местам: VPS crontab + `/root/run-alert.sh`, `.env` на VPS, GitHub Actions + secrets. Единого владельца нет — на вопрос «кому и когда уходит» приходилось собирать ответ заново, а проблемы находились случайно (2026-10-04: health-monitor реально срабатывает раз в 4–6 ч вместо 15 мин; получатель в секрете `NOTIFY_EMAIL` неизвестен).

## Роль
Админ + контроль (выбрано пользователем 2026-10-04):
- ведёт реестр алярмов (что / кому / как часто / где настроено);
- меняет адресатов и расписание по команде;
- проверяет по логам, что письма реально ушли, и сообщает о пропусках.

## Вне scope
- Создание новых алярмов — профильный агент (analytics и т.п.); после создания алярм регистрируется у alarms.
- Починка упавшего алярма — bug-agent (alarms передаёт ему собранные логи).

## Реестр
- Источник правды: `VAULT/Meeting Notes/alarms-registry.md` (приватно — адреса команды).
- Экспорт: `Desktop/AI AGENS ALARMS.xlsx`.

## Критерии успеха
- На «кому уходит X» — ответ из реестра, сверенный с источником, без повторного расследования.
- Смена адресата — одна правка в одном месте + обновлённый реестр.
- Пропущенная отправка видна при первой же проверке, а не когда кто-то пожалуется.

## Агент
- Файл: `.claude/AGENTS/alarms/AGENT.md`
- Vault: `VAULT/Meeting Notes/alarms-registry.md`

## Мониторинг (сделано 2026-10-04)
Исследование практик (Google SRE, dead man's switch, alerts as code) → выбор пользователя: **Uptime Kuma + Healthchecks**, оба self-hosted на VPS, только localhost.
- **Healthchecks** — контроль алярмов по расписанию: cron по Израилю + допуск 60 мин, пинг с кодом возврата → о пропуске или ошибке письмо Дану. Kuma для этого не подошла: push-монитор понимает только интервал (Вс–Чт = окно 72 ч, месячный алярм невозможен — переполнение таймера Node >24 дней).
- **Uptime Kuma** — `/health` через тоннель раз в минуту.
- GitHub health-monitor остаётся внешней страховкой на смерть всего VPS.

## Отклонено
- Cronicle (единая панель расписаний) и группы рассылки от IT — адресатов мало, crontab + реестр + Healthchecks достаточно (решение пользователя 2026-10-04).

## Пульт алярмов (сделано 2026-10-14)
Повод: алярмов 13, адресаты меняются почти каждую неделю, держать в голове тяжело. Цель (Дан): **один экран, чтобы видеть всё; править — по-прежнему через агента в чате**.
Исследование практик: каталог рассылок одной таблицей (Power BI admin subscriptions, BI «Scheduled Delivery»), вид «кто что получает» (аудит уведомлений), светофор последний/следующий запуск (Healthchecks), у каждого алярма «зачем / кто попросил».
- Только на компе Дана: ярлык `Desktop/COLUMBUS Alarms.lnk` с значком 🔔 (→ `~/.claude/tools/columbus-alarms/columbus-alarms.bat`, ssh → `/root/alarms-page.sh`) собирает `docs/alarms.html` со свежими данными и открывает в браузере. Вкладки: אלרמים (карточки со статусом) · מי מקבל מה (матрица люди × алярмы) · שבוע (по дням и часам).
- Сначала (66b6f59c) сделал плиткой в Formula Road для super — Дан: «кто сказал что в апп, это только мне» → убрано (0348a412), эндпоинтов на сервере нет.
- Данные: адреса вживую из `/root/run-alert.sh` + `.env` (второго места правды нет), описания — `server/data/alarms-catalog.json`, имена — `/root/alarms-people.json` (VPS), статус — Healthchecks через manage.py (без API-ключа).
- Трекинг не нужен: личный инструмент Дана, не продукт.

## Следующий шаг пульта — правка адресатов заявкой (спецификация Дана 2026-10-14, не сделано)
Схема «заявка на изменение»: Дан правит черновик на пульте → «שמור» копирует текст заявки в буфер → вставляет в чат → агент alarms сверяет с run-alert.sh/.env, озвучивает «было → станет», бэкап, правит, проверяет. Пульт остаётся локальным файлом — на сервере эндпоинта правки нет (сознательно).
- Матрица «מי מקבל מה»: клик по клетке → אל / העתק / убрать; изменённые клетки подсвечены; ✕ у человека — убрать из алярма; поле «добавить адрес» для нового человека.
- Строки сгруппированы (сверху вниз): **הנהלה** — топ-менеджмент (Дан, Йоси, Максим, Дима) · **אחראים** (Лена, Дани Б., Ханан, Александр Ф., Юваль) · **מנהלים FORMULA + משפחתי** · **מנהלים BDD** · **אחרים** (Таня, Марьяна, Юлия Д. + любой адрес вне групп — Дан 14.10: «их лучше отдельно») · **סוכנים** — один блок («כל הסוכנים — רק הלקוחות שלהם», «Изменения клиентов», адреса из EMAIL + PASSWORD.xlsx), внутри блока ✕ для отдельных агентов.
- Помечать в заявке, где нужна правка кода, а не адресов: копия у алярма без CC (מקרר), исключение агента (в client-changes-alert.js списка исключений нет — нужен `CLIENT_CHANGES_AGENT_EXCLUDE`), перенос в «מנהלים» (нужна команда — каждый получает только свою группу), «אל» в облиго = личное письмо каждому.
