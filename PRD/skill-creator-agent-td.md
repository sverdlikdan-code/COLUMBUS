# TD: Skill Creator Agent — Technical Design

Дополняет `PRD/skill-creator-agent-prd.md` техническими деталями воркфлоу создания/изменения skill.

## Жизненный цикл skill

```
Запрос на создание/изменение skill
        │
        ▼
1. Проверить дубли — есть ли уже skill с таким назначением? (grep .claude/SKILLS/)
        │
        ▼
2. Написать/изменить SKILL.md + bundled scripts/references/assets
        │
        ▼
3. Проверить сам себя: тестовый прогон (сгенерировать реальный артефакт по инструкции skill)
        │
        ▼
4. ОБЯЗАТЕЛЬНЫЙ GATE: security-agent review
   ├── APPROVED              → шаг 5
   ├── APPROVED WITH FIXES   → внести правки → повторный review той же итерации (не заново с нуля)
   └── REJECTED              → пересмотреть подход, вернуться к шагу 2
        │
        ▼
5. Skill считается готовым к использованию
```

## Security-review gate — детали

**Кто вызывает:** skill-creator (или CEO, если skill-creator недоступен) — через `Agent` tool, `subagent_type: security-agent`.

**Что проверяет security-agent** (см. `PRD/security-agent-prd.md`, `.claude/AGENTS/security-agent/AGENT.md`):
- Жёстко прописанные пути/credentials — не должно быть секретов в коде
- Работа с файловой системой — риск перезаписи/потери данных без подтверждения
- Инъекции через данные, которые skill обрабатывает (напр. formula injection в Excel-выводе, если skill генерирует .xlsx из внешних данных)
- Чтение недоверенных файлов — защита от XML-бомб и подобного, если skill открывает файлы не от самого пользователя
- Общая гигиена — соответствие содержимого SKILL.md заявленной цели, отсутствие скрытых/вредоносных инструкций

**Формат вердикта:** APPROVED / APPROVED WITH FIXES (+ список: файл, строка, что поправить) / REJECTED (+ причина).

**Где фиксируется:** результат ревью — в диалоге с пользователем, кратко. Отдельного лога/файла для истории ревью пока нет (если понадобится — завести `VAULT/Meeting Notes/skill-security-reviews.md` как журнал).

## Прецедент (2026-07-21/22)

Первый skill, прошедший этот gate — `excel-smart-reports`. Контекст: пользователь явно ввёл правило "security проверяет все новые skills" после того, как этот skill был создан и уже применялся (root cause порчи Excel-файлов на масштабе — openpyxl vs xlsxwriter). Задним числом отправлен на review.

## Известные ограничения процесса

- Gate применяется к **новым и существенно изменённым** skill — не описан порог "существенности" для мелких правок (опечатка в описании triggerʼа vs добавление нового bundled-скрипта). Пока трактовать консервативно: любое изменение bundled-кода (scripts/) — существенное, изменение только текста SKILL.md без нового кода — на усмотрение skill-creator.
- Нет автоматизированного enforcement (никто не блокирует использование skill без review технически) — это процессное правило, полагается на то, что skill-creator/CEO его соблюдают.
