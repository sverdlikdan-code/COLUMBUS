# Obligo Alert

## Обзор
Еженедельный email-алярм топ-менеджменту о сетях/клиентах, приближающихся к лимиту облиго (>=85% ניצול OBLIGO, изменено с 90% 2026-09-27). Источник — таблица `HOVOT ALL` в датасете `FORMULA DASHBORD` (workspace `DASHBORDS -ICE-INTER-FORMULA`, тот же что POWERBI_DATASET_ID в `.env`).

### 2026-09-10 #shipped
- Запрос: авто-рассылка на мейлы топ-менеджмента при превышении облиго по сети
- **Датасет найден методом исключения**: сервис-принципал видит только 2 workspace (`DASHBORDS -ICE-INTER-FORMULA`, `CONTROL`), ~40 живых DAX-запросов на угадывание имени таблицы ушли впустую, пока пользователь не дал точное имя из Power Query. Нашлись `HOVOT ALL` (2057 строк, грань — компания) и `OBLIGO` (235 строк, справочник лимитов) в `FORMULA DASHBORD`
- **Меры — только готовые из модели**, никакого ручного SUM по сырым колонкам: `[% ניצול OBLIGO]`, `[OBLIGO מנוצל]`, `[OBLIGO רב חברתי]` — совпадают с DELTA-страницей 1-в-1. Ручной SUM по сырым колонкам поначалу казался рабочим (совпадал для 1-компанийных групп типа שופרסל אקספרס), но дал неверные числа там, где легенда не совпадала с реальной агрегацией модели (напр. קונטיינר: ручной SUM ₪214,910 vs настоящая мера ₪306,792) — пользователь настоял на "только готовые DAX", это поймало реальный баг
- **Баг агрегации "דהן"**: HOVOT ALL — грань компании, но 5 разных юрлиц-франчайзи могут делить одно название `תאור סוג לקוח` (пример: "דהן" под אחראי מקסים — 5 компаний, лимиты 250k+10k+10k+200k+150k=620k). Плоский список без агрегации давал 5 фиктивных строк "דהן" с дикими % (до 1374%) вместо правильных агрегированных 176%. Исправлено — агрегация по (אחראי, имя) перед пересчётом %
- **Классификация רשתות/שוק פרטי** — живёт в отдельной таблице `לקוחות FORM+I+INT` (customer dimension), на уровне отдельных клиентских счетов, с шумом на границах (один "служебный" חנויות/שוק פרטי счёт среди множества רשתות-счетов той же сети) — классификация компании берётся по большинству голосов (mode), не по первому попавшемуся значению
- **Шум данных**: 201 из 245 первоначальных превышений — клиенты с дефолтным лимитом ровно ₪10,000 (не настоящий лимит, системный дефолт Priority для неконфигурированных счетов, подтверждено — `תיקרת האובליגו`/`אשראי רב חברתי` тоже пустые у этих компаний). Решение пользователя — не фильтровать, а показывать все 3 числа (מנוצל/רב חברתי/%) в таблице, чтобы дефолт был виден сразу
- Группировка: רשתות → блоки по `אחראי`; שוק פרטי → блоки по агенту (приоритет FORMULA→ICE→INTER), с номером клиента (`מס. לקוח`)
- MMD International Eilat исключён из алярма — собственная дочерняя компания, не внешний риск
- Дизайн (по запросу "designer + impeccable, жирнейшая визуалка"): официальный бланк Diler — белый силуэт-логотип (сгенерирован через sharp: brightness(0)+invert(1) эквивалент, `docs/logo-diler-bmd-white.png`) на сплошном navy (не градиент — CSS `linear-gradient` не рендерится во многих email-клиентах, шапка становилась прозрачной), центрированная шапка как в Formula Road app (референс пользователя). Числовые колонки — **фиксированная ширина + text-align:right**, не auto+left — иначе цифры "гуляют" по вертикали между блоками (разные таблицы на блок = разные auto-width, живой баг поймал пользователь на скриншоте)
- Персонализация: письмо шлётся отдельно каждому получателю (не один `to` на всех) с обращением по имени (`RECIPIENT_NAMES` map), sender `AI Analytics Assistant` — единый бренд с остальными уведомлениями системы (mekarer order email)
