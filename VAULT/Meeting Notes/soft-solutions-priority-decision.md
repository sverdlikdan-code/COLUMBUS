# soft-solutions-priority-decision

Решение о замене дорогого стороннего вендора Soft Solutions (модуль заказов для полевых агентов) — Formula Road + Priority OData API, либо нативный Priority Mobile App Generator (מחولל יישومونים).

## Контекст

Diler B.M.D. платит Soft Solutions за приложение ввода заказов для ~60-70 полевых агентов (FORMULA+ICE+INTER). Soft Solutions — с апреля 2022 дочка самой Priority (~50 млн₪ сделка). Formula Road (собственная разработка COLUMBUS) уже покрывает маршрутизацию/карту/менеджерские отчёты для тех же агентов — не хватает только записи заказа в Priority.

## Ключевые решения/находки

**Реальная стоимость Soft Solutions** — 147,890₪/год, найдена не в договоре, а прямой проверкой проводок Priority (FNCTRANS, поставщик "Priority Software Ltd", централизовано через компанию diller). Покрывает всю группу, не только FORMULA.

**Механизм Soft Solutions без отдельного API** — заказы создаются под ~80 индивидуальными Priority-логинами агентов (ORDERS.T$USER, стабильная связь 1:1 с AGENT), не через сервис-аккаунт/API. Это персональное мобильное лицензирование, доступное и через מחولл.

**Formula Road не может повторить этот трюк** — отдельный PWA не имеет доступа к внутреннему протоколу "Priority Mobile"-контейнера. Нужен либо OData write-API (платный, требования: API-модуль + API-лицензия на пользователя + transaction package), либо перенос экрана заказа внутрь מחولл (тогда два приложения у агента).

**Официальные источники прочитаны полностью** — Priority_App_Generator_H_24_1.pdf (LBI2400579, июнь'26), Priority_OData_API_H.pdf (LB150474, авг'26). Ключевой факт из OData-гайда: read+write транзакции считаются в ОДИН лимит лицензии, не раздельно (опровергает старые форумные слухи "read бесплатен").

**Попытка полного P&L из GL Priority провалила проверку на здравый смысл** — наивный запрос по TRIALBAL даёт COGS≈0 и расходы>выручки. Причина не найдена (возможно COGS признаётся через INVOICEITEMS.IVCOST, не через FNCTRANS). Задокументировано как открытая проблема в priority-sql skill — не повторять тот же неудачный подход. Рабочий метод для Revenue/COGS отдельно (через INVOICEITEMS, дал разумную маржу 1-10%) — найден и работает.

**Excel-анализ расходов по 4 категориям (IT/Аренда/Транспорт/Маркетинг) 2023-2026** — собран, IT-бюджет группы вырос +210% за 2 года (819К→2.5-3.1М₪).

**Попытка автоматизировать сборку יישومون через Puppeteer на реальном профиле Edge пользователя — заблокирована защитным механизмом Claude Code** (слишком рискованное действие с боевой ERP-сессией). Решение: создан агент `priority-app` для ведения темы, сборка внутри Priority Web остаётся ручной (пользователь + пошаговые инструкции), не автоматизированной.
